# Общие правила v5

## Не выдумывать

Запрещается придумывать шаги Vanessa, элементы формы, команды, реквизиты, ожидаемые результаты, бизнес-логику и предусловия.

Исключение: для реквизитов со свободным вводом разрешено генерировать тестовые значения, если они соответствуют типу/формату реквизита.

Если информация отсутствует или не подтверждена через MCP:

```text
ТРЕБУЕТ УТОЧНЕНИЯ
```

## Изменение данных

Данные в базе можно менять только через существующие шаги Vanessa Automation, если это прямо следует из тест-кейса.

Разрешено через Vanessa:

- нажимать кнопки;
- заполнять поля;
- создавать документы через UI;
- проводить документы через UI;
- менять статусы через UI;
- выполнять действия пользователя, которые предусмотрены тест-кейсом.

Запрещено менять данные через:

- `execute_query`;
- `execute_code`;
- BSL;
- прямую запись объектов через MCP;
- проведение документов через MCP;
- изменение регистров через MCP.

## Получение тестовых данных

Тестовые данные из базы получать через ROCTUP/1c-mcp-toolkit.

Разрешены только:

- `get_metadata`;
- `execute_query`;
- `get_object_by_link`;
- `get_link_of_object`.

`execute_query` используется только для read-only запросов языка запросов 1С.

`execute_code` запрещен.

## Генерация тестовых данных для свободного ввода

Если тест-кейс требует заполнить реквизит и реквизит поддерживает свободный ввод, значение можно сгенерировать.

Перед генерацией значения нужно определить через EDT-MCP:

- тип реквизита;
- формат;
- маску;
- длину;
- обязательность;
- допустимые символы;
- признак свободного ввода.

Если формат известен — значение должно строго соответствовать формату.

Примеры:

- строка без формата: `Автотест <уникальный_суффикс>`;
- число: положительное число в допустимом диапазоне;
- дата: дата в формате, принятом в форме;
- код/номер с маской: значение по маске;
- булево: `Истина` или `Ложь`;
- перечисление/выбор из списка: не генерировать, а выбирать существующее значение.

Если свободный ввод не подтвержден — не генерировать значение, а искать существующее значение через `execute_query` или возвращать `ТРЕБУЕТ УТОЧНЕНИЯ`.

## Подбор похожих элементов формы

Если EDT-MCP не нашел элемент формы, кнопку или команду по точному имени/заголовку из тест-кейса, разрешается искать похожий по смыслу элемент.

Примеры допустимых смысловых замен:

- `Готово` → `Провести`;
- `Готово` → `Завершить`;
- `Готово` → `Завершить редактирование`;
- `ОК` → `Выбрать`;
- `Сохранить` → `Записать`;
- `Сохранить и закрыть` → `Записать и закрыть`;
- `Закончить` → `Завершить`.

Подбор разрешен только если:

1. найденный элемент реально существует и подтвержден через EDT-MCP;
2. действие найденного элемента совпадает по бизнес-смыслу с тест-кейсом;
3. для действия есть существующий шаг Vanessa;
4. замена не меняет ожидаемый результат;
5. в feature добавлен комментарий о замене.

Формат комментария:

```gherkin
# Элемент "<Исходное имя>" не найден. Использован похожий по смыслу элемент "<Фактическое имя>", подтвержденный через EDT-MCP.
```

Если смысловая замена неоднозначна — вернуть `ТРЕБУЕТ УТОЧНЕНИЯ`.

## Критичность отсутствующих элементов

Критичный элемент — без него невозможно выполнить основной сценарий или проверить основной ожидаемый результат.

Если отсутствует критичный элемент и нельзя однозначно подобрать похожий по смыслу элемент — feature не генерировать.

Если отсутствует некритичный элемент — feature можно генерировать, но добавить комментарий:

```gherkin
# Реквизит "<Имя>" не найден в актуальной форме. Проверка пропущена, требуется актуализация тест-кейса.
```

## Критерий готовности

Feature готов, если:

- каждый исполняемый шаг найден через Vanessa AI MCP;
- каждый критичный элемент подтвержден через EDT-MCP или однозначно сопоставлен с похожим элементом;
- все тестовые данные из базы найдены через `execute_query`;
- сгенерированные значения для свободного ввода соответствуют формату;
- изменения данных выполняются только шагами Vanessa;
- все замены и пропуски отражены комментариями;
- нет BSL;
- нет `execute_code`;
- сценарий соответствует тест-кейсу.
