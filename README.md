# AI Framework for 1C Vanessa Automation Test Generation

Framework для генерации **исполняемых** автотестов Vanessa Automation по тест-кейсам с использованием LLM (Codex) и MCP.

Основная идея — LLM **не придумывает** структуру приложения, шаги или тестовые данные. Вся информация получается из специализированных MCP-серверов.

---

# Архитектура

```text
                Test Case
                    │
                    ▼
            Planner Agent
                    │
                    ▼
      Vanessa Knowledge Agent
     (поиск похожих автотестов)
                    │
                    ▼
              EDT Agent
 (формы, команды, реквизиты, UI)
                    │
                    ▼
             Query Agent
     (поиск тестовых данных)
                    │
                    ▼
      Vanessa Knowledge Agent
      (поиск существующих шагов)
                    │
                    ▼
          Feature Generator
                    │
                    ▼
          Validator Agent
                    │
                    ▼
        Ready *.feature file
```

# Используемые MCP

## EDT-MCP

Repository:

https://github.com/DitriXNew/EDT-MCP

Используется для получения информации о конфигурации 1С:

- формы;
- элементы формы;
- команды;
- реквизиты;
- табличные части;
- типы реквизитов;
- форматы данных;
- возможность свободного ввода;
- поиск похожих элементов формы;
- навигационные ссылки;
- объекты метаданных.

EDT-MCP является **единственным источником истины** для структуры конфигурации. :contentReference[oaicite:0]{index=0}

---

## Vanessa Automation AI

Repository:

https://github.com/1c-neurofish/onec-client-mcp-devkit

Documentation:

https://github.com/Pr-Mex/vanessa-automation/blob/develop/docs/AI/index.md

Используется для работы с проектом автотестов.

Получает:

- существующие Feature;
- существующие Scenario;
- существующие шаги Vanessa Automation;
- примеры использования шагов;
- стиль оформления проекта.

LLM запрещено придумывать собственные шаги.

---

## 1C MCP Toolkit

Repository:

https://github.com/ROCTUP/1c-mcp-toolkit

Используется только для получения данных информационной базы.

Основные инструменты:

- `get_metadata`
- `execute_query`
- `get_object_by_link`
- `get_link_of_object`

Используется для:

- поиска тестовых данных;
- поиска документов;
- поиска элементов справочников;
- получения структуры объектов;
- получения объектов по ссылке.

Все запросы выполняются только в режиме **read-only**. Инструментарий поддерживает получение метаданных и данных из базы через MCP/REST. :contentReference[oaicite:1]{index=1}

# Принципы генерации

## 1. Не придумывать

LLM запрещено придумывать:

- шаги Vanessa;
- элементы формы;
- команды;
- реквизиты;
- тестовые данные из базы;
- бизнес-логику.

Если информацию невозможно подтвердить через MCP — вернуть `ТРЕБУЕТ УТОЧНЕНИЯ`.

---

## 2. Приоритет источников

При выполнении задачи используется следующий порядок:

1. Найти похожий автотест через Vanessa AI.
2. Подтвердить UI через EDT-MCP.
3. Подобрать тестовые данные через 1c-mcp-toolkit.
4. Сгенерировать `.feature`.
5. Выполнить валидацию.

---

## 3. Изменение данных

Во время выполнения автотеста изменение данных **разрешено**, но только пользовательскими действиями через существующие шаги Vanessa Automation.

Например:

- создание документа;
- проведение документа;
- изменение статуса;
- запись формы.

Запрещено изменять данные через:

- `execute_code`;
- BSL;
- MCP write-инструменты;
- прямую запись объектов.

---

## 4. Получение тестовых данных

Если тест-кейс требует существующие данные:

- используется `execute_query`;
- при необходимости сначала вызывается `get_metadata`;
- используются только read-only запросы.

---

## 5. Свободный ввод

Если поле поддерживает свободный ввод:

- значение генерируется автоматически;
- формат определяется через EDT-MCP;
- значение должно соответствовать типу, маске и ограничениям поля.

Если поле является выбором из списка — используется существующее значение из базы.

---

## 6. Смысловая замена элементов

Если EDT-MCP не находит элемент по точному названию, допускается поиск похожего по смыслу элемента.

Например:

- `Готово` → `Провести`
- `Готово` → `Завершить`
- `Сохранить` → `Записать`
- `Сохранить и закрыть` → `Записать и закрыть`

Замена допускается только если:

- элемент найден через EDT-MCP;
- бизнес-смысл совпадает;
- существует соответствующий шаг Vanessa;
- в `.feature` добавлен комментарий.

---

## 7. Некритичные отличия

Если документация устарела и отсутствует только дополнительный реквизит, допускается генерация автотеста.

В `.feature` добавляется комментарий:

```gherkin
# Реквизит "Гриф доступа" не найден.
# Проверка пропущена.
# Требуется актуализация тест-кейса.
```

Если отсутствует критичный элемент, генерация прекращается.

---

# Критерий готовности

Автотест считается готовым только если:

- используются только существующие шаги Vanessa;
- все критичные элементы подтверждены EDT-MCP;
- тестовые данные получены через `execute_query` или корректно сгенерированы для свободного ввода;
- отсутствует BSL;
- отсутствует `execute_code`;
- все изменения данных выполняются только через UI;
- Validator Agent завершился успешно.
