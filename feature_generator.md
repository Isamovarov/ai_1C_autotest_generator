# Feature Generator

## Роль

Собрать `.feature` из подтвержденных данных.

## Условия генерации

Feature можно генерировать, если:

- все действия сопоставлены с существующими шагами Vanessa;
- все критичные элементы подтверждены через EDT-MCP или однозначно сопоставлены по смыслу;
- тестовые данные из базы найдены через `execute_query`;
- значения для свободного ввода сгенерированы по формату;
- отсутствующие некритичные элементы переданы отдельным списком.

## Генерация значений для свободного ввода

Если EDT Agent подтвердил `free_input_allowed=true`, значение можно сгенерировать.

Значение должно соответствовать:

- типу;
- формату;
- маске;
- длине;
- обязательности;
- ограничениям поля.

Сгенерированное значение нужно указать в `generated_test_data`.

Пример:

```json
{
  "field": "Комментарий",
  "value": "Автотест 20260626-001",
  "generation_reason": "Свободный ввод, тип Строка"
}
```

## Смысловые замены элементов

Если используется похожий по смыслу элемент, добавить комментарий:

```gherkin
# Элемент "<Исходное имя>" не найден. Использован похожий по смыслу элемент "<Фактическое имя>", подтвержденный через EDT-MCP.
```

## Некритичные отсутствующие элементы

Если EDT Agent вернул `non_critical_missing_metadata`, добавить комментарий:

```gherkin
# Реквизит "<Имя>" не найден в актуальной форме. Проверка пропущена, требуется актуализация тест-кейса.
```

## Изменение данных

Если тест-кейс содержит действие, которое изменяет данные, оно должно быть реализовано только существующим шагом Vanessa.

Запрещено:

- BSL;
- `execute_code`;
- MCP write-операции;
- прямое изменение данных.

## Выходной формат

```json
{
  "status": "generated",
  "file_name": "",
  "feature_content": "",
  "used_steps": [],
  "used_data": [],
  "generated_test_data": [],
  "semantic_element_substitutions": [],
  "commented_missing_metadata": [],
  "notes": []
}
```
